# Gongkao Sprint Design Document

## 1. 设计目标

`Gongkao Sprint` 第一版是一款桌面优先、手机轻量可用的 Obsidian 行测备考工作台插件。产品面向希望开箱即用的小红书公考用户，核心体验是：用户在桌面端进入一个全屏感较强的备考工作台，直接看到今天该刷什么、错题该复习哪些、当前专题或套卷推进到什么状态；手机端优先满足拍照新增错题、记录刷题和开始复习。

本设计文档基于前期产品讨论和 `spec.md`，并纳入以下确认结论：

- 工作台使用 Obsidian 主区域自定义 View，尽量提供接近全屏 App 的体验。
- 一道错题对应一个 Markdown 文件。
- 刷题集合不要求用户预先计算总题数，也不以页码作为核心进度单位。
- 刷题集合进度按“专题/套卷/自定义刷题集合”组织，由刷题记录驱动。
- 用户界面统一称为“刷题集合”，代码概念使用 `PracticeCollection`。
- 刷题集合、刷题记录和错题卡通过稳定 `collection_id` 关联，同时保留集合名称保证 Markdown 可读。
- 错题支持纯文本卡和带图片卡。
- 新建错题时，初始 `next_review` 根据初始掌握度生成。
- 复盘记录是核心功能，用于沉淀技巧、思维惯性、触发场景和下次纠偏动作。
- 备考努力热力图用于展示备考周期内的每日投入，并为后续分享内容预留基础。
- 图片支持本地选择、拖拽和剪贴板粘贴。
- 图片遮挡首版只支持多个矩形遮罩。
- 每日计划使用轻规则推荐。
- 二刷作为独立轮次统计，不重置首刷进度。
- 首次打开提供“一键创建示例”，不自动污染用户 Vault。

## 2. 产品结构

第一版包含 5 个主要体验模块：

- 全屏工作台
- 专题/套卷进度

- 复盘记录
- 备考努力热力图
- 图片遮挡编辑
- 今日复习与计划推荐

## 3. 主区域工作台设计

### 3.1 入口

插件注册一个主区域自定义 View：

```ts
const VIEW_TYPE_GONGKAO_DASHBOARD = "gongkao-sprint-dashboard";
```

入口方式：

- Ribbon 图标打开工作台。
- Command Palette 命令：`Open Gongkao Dashboard`。
- 插件首次启用后可弹出提示，引导用户打开工作台。

工作台应尽量占据 Obsidian 主编辑区。用户可以通过 Obsidian 自身的布局能力将其最大化或独立放置。

### 3.2 页面布局

桌面端建议三栏布局：

```text
┌────────────────────────────────────────────────────────────┐
│ 顶部：今日日期 / 快速操作                                  │
├───────────────────┬─────────────────────┬──────────────────┤
│ 今日计划           │ 今日复习             │ 当前刷题集合      │
│ - 倒计时           │ - 到期错题           │ - 专题/套卷卡片   │
│ - 待刷题           │ - 开始复习按钮       │ - 本周刷题概览    │
│ - 今日完成率       │ - 最近错题入口       │ - 最近复盘        │
├───────────────────┴─────────────────────┴──────────────────┤
│ 第二行：本周刷题概览 / 最近复盘 / 薄弱与纠偏提醒              │
├────────────────────────────────────────────────────────────┤
│ 第三行：学习日历与备考热力图（左 35% 日历 / 右 65% 热力图）    │
└────────────────────────────────────────────────────────────┘
```

当 Obsidian 窗口较窄时，布局降级为单列纵向排列。

### 3.3 快速操作

顶部固定放置 5 个操作，顺序固定：

- 制定今日计划
- 记录刷题
- 新增错题
- 新增复盘
- 开始复习

这些按钮应使用明确动词，减少用户理解成本。新建专题/套卷/题集不再作为顶部操作，应内置在记录刷题弹窗和专题进度空状态中。

## 4. 专题/套卷模型

### 4.1 命名调整

早期讨论中的“题集”在产品界面中统一命名为“刷题集合”，并提供三种类型：

- 专题：如“资料分析增长率专项”“判断推理图形推理”
- 套卷：如“2024 国考地市级行测真题”
- 书籍：如“粉笔行测5000题”

这样可以避免要求用户录入一本书的总题数，也更贴近实际刷题习惯。

### 4.2 进度原则

首版不要求用户输入总题数。进度由刷题记录自然累积。

工作台展示的核心指标：

- 累计刷题数
- 累计错题数
- 最近一次刷题日期
- 当前轮次
- 是否首刷完成
- 到期复习错题数

“完成”由用户手动标记，而不是由总题数自动推导。

原因：

- 用户通常不会重新计算整本题集总题数。
- 不同题集有专题、套卷、章节、附赠题，统计口径不稳定。
- 手动标记“首刷完成”更符合纸质刷题体验。

### 4.3 数据结构

刷题集合 Markdown 文件存放在：

```text
Gongkao Sprint/05_专题训练/
```

frontmatter：

```yaml
type: gongkao-practice-collection
collection_id: pc_20260729_001
name: 资料分析增长率专项
collection_type: topic
subject: 行测
module: 资料分析
status: active
current_round: 1
created: 2026-07-29
updated: 2026-07-29
```

`collection_type` 枚举：

```ts
type CollectionType = "topic" | "paper" | "book";
```

`status` 枚举：

```ts
type CollectionStatus =
  | "not_started"
  | "active"
  | "first_round_done"
  | "second_round"
  | "paused";
```

统计字段如累计题数和错题数不强制写入 frontmatter，可以由刷题记录计算。为了性能，后续可以增加缓存字段，但 Markdown 刷题记录仍是事实来源。

### 4.4 刷题记录

每次刷题生成一条刷题记录：

```yaml
type: gongkao-practice-log
date: 2026-07-29
collection_id: pc_20260729_001
collection_name: 资料分析增长率专项
collection_type: topic
module: 资料分析
total: 40
wrong: 8
duration_minutes: 60
round: 1
created: 2026-07-29T20:00:00+08:00
```

可选字段：

```yaml
source: 粉笔行测5000题
range_label: 第 41-80 题
note: 增长率公式专项
```

`range_label` 是自由文本，用于记录“第 41-80 题”“P132 附近”“2024 国考第 91-110 题”等用户熟悉的定位方式，不参与统计计算。

## 5. 错题卡片设计

### 5.1 文件粒度

确认采用“一道错题 = 一个 Markdown 文件”。

优势：

- 每张卡可独立复习排期。
- 每张卡可独立绑定图片和遮挡区域。
- 工作台统计和复习队列实现更简单。
- 用户卸载插件后仍可逐题阅读。

### 5.2 错题 frontmatter

```yaml
type: gongkao-error-card
subject: 行测
module: 资料分析
question_type: 增长率
collection_id: pc_20260729_001
collection_name: 资料分析增长率专项
collection_type: topic
source: 粉笔行测5000题
range_label: 第 47 题
round: 1
answer: B
wrong_reason: 公式混淆
mastery: 1
review_count: 0
created: 2026-07-29
last_reviewed:
next_review: 2026-08-01
status: active
image: Attachments/2026-07-29-资料分析-001.jpg
masks:
  - x: 620
    y: 180
    width: 260
    height: 140
    label: 手写解析
review_history: []
```

无图片错题允许省略 `image` 和 `masks` 字段，并使用正面文字进入复习。

### 5.3 错题正文

```markdown
# 资料分析错题 - 增长率

## 正面

![[Attachments/2026-07-29-资料分析-001.jpg]]

问题：这题考什么？

## 背面

正确答案：B

核心突破口：

我的错因：

下次提醒自己：
```

正文尽量固定结构，让轻度用户不用自己设计模板。

### 5.4 初始复习日期

新建错题卡时，`next_review` 根据初始掌握度生成：

- 不会：明天
- 模糊：3 天后
- 基本会：7 天后
- 熟练：21 天后

## 6. 复盘记录设计

### 6.1 设计目标

复盘记录用于承接公考备考中最重要的“方法和惯性”沉淀。它不是自由日记，而是结构化记录：

- 这次问题在什么场景触发。
- 我暴露了什么思维惯性。
- 有什么技巧或方法需要保留。
- 下次遇到同类题要执行什么纠偏动作。

### 6.2 复盘类型

首版内置复盘类型：

- 技巧沉淀
- 思维惯性
- 易错提醒
- 时间策略
- 方法步骤
- 其他

### 6.3 关联范围

复盘记录可以关联：

- 当天整体复盘
- 一次刷题记录
- 一张错题卡
- 一个刷题集合
- 一个行测模块

### 6.4 数据结构

复盘记录存放在：

```text
Gongkao Sprint/06_复盘记录/
```

frontmatter：

```yaml
type: gongkao-reflection-log
reflection_id: rf_20260729_001
date: 2026-07-29
scope: error_card
module: 资料分析
collection_id: pc_20260729_001
collection_name: 资料分析增长率专项
error_card_path: 03_错题库/2026-07-29-资料分析-001.md
reflection_type: 思维惯性
created: 2026-07-29T21:00:00+08:00
updated: 2026-07-29T21:00:00+08:00
```

正文模板：

```markdown
# 资料分析复盘 - 思维惯性

## 触发场景

## 我的问题

## 技巧/方法

## 下次纠偏动作
```

### 6.5 工作台呈现

工作台展示最近复盘记录，并在“薄弱与纠偏提醒”中纳入复盘信号。例如同一模块最近 7 天出现 2 条以上“思维惯性”复盘，应提示用户进行专项纠偏。

## 7. 备考努力热力图

### 7.1 设计目标

热力图用于展示备考周期内的每日投入，让用户直观看到自己持续推进的证据。它应给用户稳定反馈，而不是制造焦虑。后续可以作为小红书分享图的数据基础，但 MVP 不做导出。

### 7.2 数据来源

每日努力值由以下数据汇总：

- 当日刷题记录数量和刷题总量。
- 当日复习记录数量。
- 当日复盘记录数量。
- 当日计划完成率。

### 7.3 展示规则

工作台展示最近 90 天热力图，并与当前月学习日历合并为一个横向时间管理卡片。卡片左侧为学习日历，右侧为热力图，比例约为 35% / 65%。颜色深浅代表努力值强弱，不展示复杂公式。无数据日期显示为空格或最低强度。

### 7.4 交互

鼠标悬停某一天时展示：

- 日期。
- 刷题数。
- 复习数。
- 复盘数。
- 计划完成率。

点击某一天时，可以打开对应每日计划或当天记录列表。

## 8. 图片录入与遮挡

### 8.1 支持来源

首版支持：

- 从本地选择图片。
- 拖拽图片到新增错题弹窗。
- 从剪贴板粘贴截图或图片。
- 手机端拍照或从相册选择图片。

首版不支持：

- PDF 内直接截图。
- OCR。
- AI 自动识别答案区。

### 8.2 附件处理

图片统一复制到：

```text
Gongkao Sprint/08_资源库/Attachments/
```

命名规则：

```text
{date}-{module}-{sequence}.{ext}
```

示例：

```text
2026-07-29-资料分析-001.jpg
```

### 8.3 遮挡能力

首版只支持多个矩形遮罩。

用户操作：

- 在图片上拖拽创建遮挡区域。
- 可以移动、缩放、删除遮挡区域。
- 可以为遮挡区域设置可选标签，如“答案”“手写解析”。
- 可以跳过遮挡，直接保存整图。

遮挡坐标以原图自然尺寸为基准保存，渲染时按比例缩放。

```ts
interface ImageMask {
  x: number;
  y: number;
  width: number;
  height: number;
  label?: string;
}
```

复习时：

- 正面显示带遮挡的图片。
- 背面显示完整图片和背面 Markdown 内容。

## 9. 复习流程设计

### 9.1 今日复习队列

进入工作台时，插件查询：

```text
status = active
next_review <= today
```

并按以下顺序排序：

- 逾期天数更久的优先。
- 掌握度更低的优先。
- 创建时间更早的优先。

### 9.2 复习界面

复习 View 使用卡片式流程：

```text
错题正面
-> 显示背面
-> 选择掌握度
-> 更新排期
-> 下一题
```

掌握度按钮：

- 不会
- 模糊
- 基本会
- 熟练

### 9.3 排期规则

第一版不实现完整 FSRS，使用轻量动态规则。

```ts
type ReviewResult = "again" | "hard" | "good" | "easy";
```

映射：

```text
again -> 不会
hard -> 模糊
good -> 基本会
easy -> 熟练
```

规则：

- 不会：掌握度降到 0，1 天后复习。
- 模糊：掌握度最多为 1，3 天后复习。
- 基本会：掌握度至少为 2，`7 + review_count` 天后复习，最多 14 天。
- 熟练：掌握度为 3，`21 + review_count * 3` 天后复习，最多 45 天。

更新字段：

- `mastery`
- `review_count`
- `last_reviewed`
- `next_review`
- `review_history`

`review_history` 示例：

```yaml
review_history:
  - date: 2026-07-29
    result: hard
    next_review: 2026-08-01
```

## 10. 今日计划生成

### 10.1 原则

首版使用轻规则推荐，不做 AI 计划。

计划生成依据：

- 今日到期错题数量。
- 默认主刷题集合。
- 最近 7 天薄弱与纠偏信号。
- 用户最近一次刷题记录。

### 10.2 推荐规则

生成今日计划时：

- 如果有到期错题，加入“复习今日到期错题 N 题”。
- 如果设置了主刷题集合，加入“继续推进主刷题集合”。
- 如果最近 7 天存在薄弱与纠偏信号，加入对应模块专项训练。
- 如果最近存在“思维惯性”复盘，加入对应纠偏提醒。
- 如果今天没有刷题记录，加入“记录今日刷题”提醒。

示例：

```markdown
---
type: gongkao-daily-plan
date: 2026-07-29
created: 2026-07-29T09:00:00+08:00
---

# 2026-07-29 行测计划

- [ ] 复习今日到期错题 12 题
- [ ] 资料分析增长率专项 40 题
- [ ] 判断推理薄弱与纠偏复盘 20 分钟
- [ ] 回看资料分析思维惯性复盘
- [ ] 整理新增错题
```

## 11. 首次使用体验

### 11.1 不自动创建示例数据

插件首次启用后不自动写入示例刷题集合、错题或计划，避免污染用户 Vault。

### 11.2 空状态引导

工作台空状态展示：

- 创建第一个刷题集合
- 记录一次刷题
- 新增一张错题卡
- 新增一条复盘记录
- 一键创建示例数据

“一键创建示例数据”由用户主动点击触发。

### 11.3 示例数据

示例数据建议创建：

- 示例专题：资料分析增长率专项
- 示例刷题记录：40 题，错 8 题
- 示例错题卡：带占位图片说明或纯文本卡
- 示例复盘记录：资料分析思维惯性
- 示例今日计划

示例数据文件名应明显包含 `示例`，方便用户删除。

## 12. 数据访问设计

### 12.1 事实来源

Markdown 文件和 frontmatter 是唯一事实来源。

插件不使用 SQLite 或独立 JSON 数据库存储核心数据。

### 11.2 服务划分

```text
VaultStore
  负责路径、文件创建、frontmatter 读写、附件复制

PracticeCollectionService
  负责刷题集合 CRUD 和状态更新

PracticeLogService
  负责刷题记录创建和查询

ErrorCardService
  负责错题卡创建、查询、更新

ReflectionLogService
  负责复盘记录创建、查询、关联和统计

ReviewScheduler
  负责复习队列和下次复习日期计算

StatsService
  负责工作台统计、薄弱与纠偏判断、本周刷题概览和热力图数据汇总
```

### 12.3 缓存策略

MVP 可以每次打开工作台时扫描 `Gongkao Sprint` 目录并解析 frontmatter。

后续如性能不足，再引入内存缓存：

- 监听 Vault 文件变更。
- 工作台激活时增量刷新。
- 不将缓存作为持久化事实来源。

## 13. UI 设计原则

### 13.1 面向轻度用户

界面应避免大量 Obsidian 专业概念，例如 frontmatter、metadata、query。用户看到的是：

- 刷题集合
- 今日计划
- 今日复习
- 错题卡
- 复盘记录
- 努力热力图
- 薄弱与纠偏提醒

### 13.2 低自由度

首版固定字段和固定流程，不提供复杂自定义表单。

允许用户自由填写的字段：

- 刷题集合名称
- 来源
- 范围说明
- 核心突破口
- 我的错因
- 下次提醒自己
- 触发场景

## 15. MVP 开发顺序

- 新增错题卡。

## 16. 验收标准

MVP 完成时应满足：

- 工作台可以在 Obsidian 主区域打开，并具备接近全屏工作台体验。
- 用户可以创建专题、套卷或书籍类型的刷题集合。
- 用户不需要输入总题数，也可以通过刷题记录看到累计推进。
- 用户可以手动标记首刷完成，完成后 UI 中标灰。
- 用户可以记录一次刷题，并在工作台看到累计题数、错题数和最近记录。
- 用户可以创建一题一文件的错题卡。
- 用户可以创建复盘记录，并关联错题、刷题集合、模块或当天。
- 用户可以通过本地选择、拖拽或剪贴板粘贴添加题目图片。
- 用户可以添加多个矩形遮罩。
- 复习正面显示遮罩图，背面显示完整图和解析内容。
- 用户选择掌握度后，错题卡自动更新下次复习日期。
- 今日计划可以根据到期错题、主刷题集合和薄弱与纠偏信号生成。
- 工作台可以展示最近复盘，并根据“思维惯性”复盘提示专项纠偏。
- 工作台可以展示备考努力热力图，并能反映刷题、复习、复盘和计划完成情况。
- 首次使用不会自动写入示例数据，用户可以主动一键创建示例。
- 所有核心数据均保存在 Markdown 文件和 frontmatter 中。

## 17. 明确不做

第一版不做：

- 手机端完整大屏统计工作台。
- 手机端图片遮挡编辑。
- AI 解析。
- OCR。
- 内置题库。
- PDF 内截图。
- 复杂图表。
- 热力图导出分享图。
- 自定义数据字段系统。
- 申论、面试、事业单位或教师编扩展。
- 用户账号、云同步或社区打卡。
