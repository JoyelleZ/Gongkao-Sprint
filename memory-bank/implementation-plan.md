# Implementation Plan

## 使用说明

本计划面向 AI 开发者。请严格按顺序执行，每一步只完成指定范围。每一步完成后必须执行对应验证，验证未通过不得进入下一步。本文档只提供指令，不包含代码。

全局约定：

- 若文档之间存在冲突，以 `memory-bank/design-document.md` 为准，其次参考 `spec.md` 和 `memory-bank/tech-stack.md`。
- 涉及界面、样式、交互或用户流程时，必须遵循 `memory-bank/frontend-design.md`。
- 用户界面统一称为“刷题集合”，代码概念统一使用 `PracticeCollection`。
- 刷题集合文件存放在 `Gongkao/Collections/`。
- 刷题集合、刷题记录和错题卡必须通过稳定 `collection_id` 关联，同时保留集合名称用于 Markdown 可读性。
- 错题卡必须同时支持纯文本错题和带图片错题。
- 复盘记录必须作为核心功能实现，代码概念使用 `ReflectionLog`，文件存放在 `Gongkao/Reflections/`。
- 备考努力热力图必须在工作台展示，数据来自刷题、复习、复盘和计划完成率；MVP 不做导出分享图。
- 今日计划必须生成 `Gongkao/Plans/YYYY-MM-DD.md`，工作台读取该文件展示。
- 人工验收使用一个干净测试 Vault。建议在本机创建单独的临时 Obsidian vault，不要使用真实备考 vault。

## Phase 1: 项目初始化

### Step 1: 初始化 Obsidian 插件骨架

创建 TypeScript Obsidian 插件基础项目，包含插件清单、入口文件、样式文件、构建配置和包管理文件。插件名称使用 `Gongkao Sprint`，插件 id 使用 `gongkao-sprint`。

验证：

- 确认根目录存在插件发布所需文件。
- 运行依赖安装命令成功。
- 运行开发构建命令成功生成插件入口产物。

### Step 2: 配置代码质量工具

配置 TypeScript strict mode、ESLint、Prettier 和 Vitest。保持工具配置轻量，不引入 React、Vue、Svelte 或额外运行时框架。

验证：

- 运行类型检查命令通过。
- 运行 lint 命令通过。
- 运行测试命令通过，即使此时只有空测试或示例测试。

### Step 3: 创建源码目录结构

创建 `src` 下的入口、设置、常量、类型、视图、弹窗、服务、组件和工具目录。目录命名应与 `memory-bank/tech-stack.md` 保持一致。

验证：

- 确认目录结构完整。
- 确认构建命令仍然通过。
- 确认没有无用框架依赖被加入。

## Phase 2: 插件入口与设置

### Step 4: 注册插件生命周期

实现插件加载和卸载流程。加载时注册命令、Ribbon 图标和主区域工作台 View。卸载时清理已注册资源。

验证：

- 在 Obsidian 中启用插件无报错。
- Command Palette 能看到打开工作台命令。
- 点击 Ribbon 图标能打开空工作台。

### Step 5: 实现设置页

添加设置页，包含数据根目录、附件目录、默认主刷题集合、是否启用图片遮挡、是否显示示例入口、考试日期。

验证：

- 修改每个设置项后重启 Obsidian，设置仍然保留。
- 设置为空或非法路径时有合理默认值。
- 类型检查和测试命令通过。

### Step 6: 初始化 Vault 数据目录

首次使用时，仅在用户触发相关操作时创建 `Gongkao` 数据目录及子目录，不自动创建示例数据。

验证：

- 刚启用插件时不会写入示例文件。
- 点击创建数据目录相关操作后，目录结构正确出现。
- 重复触发初始化不会创建重复目录或报错。

## Phase 3: 数据访问层

### Step 7: 实现 VaultStore

实现统一的路径管理、文件存在检查、Markdown 文件创建、附件复制和 frontmatter 读写能力。核心数据必须保存在 Markdown 和 YAML frontmatter 中。

验证：

- 使用测试 Vault 创建文件成功。
- frontmatter 写入后可以被 Obsidian metadata cache 读取。
- 对不存在目录的写入会自动创建必要目录。

### Step 8: 定义核心数据类型

定义刷题集合、刷题记录、错题卡、复盘记录、图片遮罩、复习结果、每日计划和行测模块的数据结构。字段命名应与 `memory-bank/design-document.md` 保持一致。刷题集合必须包含稳定 `collection_id`，复盘记录必须包含稳定 `reflection_id`。

验证：

- 类型检查通过。
- 构造最小合法对象不报错。
- 新建刷题集合时能生成稳定且不重复的 `collection_id`。
- 新建复盘记录时能生成稳定且不重复的 `reflection_id`。
- 缺失可选字段时服务层能使用默认值。

### Step 9: 实现文件名清理工具

实现跨平台安全文件名生成规则，用于刷题集合、错题卡、刷题记录和附件。

验证：

- 含有斜杠、冒号、问号、引号等字符的名称会被安全替换。
- 中文名称保留可读性。
- 重名时能生成不冲突的文件名。

## Phase 4: 刷题集合与记录

### Step 10: 实现刷题集合服务

支持创建、读取、更新和查询刷题集合。集合类型支持专题、套卷和书籍。首版不要求用户输入总题数。文件存放在 `Gongkao/Collections/`，每个集合必须写入稳定 `collection_id`。

验证：

- 创建专题、套卷、书籍三类集合均成功。
- 每个集合都有稳定 `collection_id`，重复刷新或改名不会改变该 ID。
- 生成的 Markdown 文件可直接阅读。
- 查询结果只包含合法刷题集合文件。

### Step 11: 实现刷题记录服务

支持记录一次刷题，字段包括日期、`collection_id`、集合名称、模块、刷题数、错题数、时长、轮次和范围说明。

验证：

- 创建刷题记录后生成独立 Markdown 文件。
- 统计时能正确按 `collection_id` 和模块聚合刷题数与错题数。
- 集合改名后，历史刷题记录仍能归属到原集合。
- 刷题数或错题数非法时阻止保存并提示。

### Step 12: 实现首刷完成状态

支持用户手动将刷题集合标记为首刷完成。完成后不重置任何刷题记录，二刷作为新轮次继续记录。

验证：

- 标记完成后集合状态更新。
- 工作台中完成集合呈现标灰状态。
- 新增二刷记录不会覆盖首刷记录。

## Phase 5: 工作台基础视图

### Step 13: 实现主区域工作台布局

实现主区域自定义 View，包含顶部操作区、今日计划与倒计时、今日复习、当前刷题集合、本周刷题概览、最近复盘、薄弱与纠偏提醒和备考努力热力图区域。

验证：

- 工作台可在主编辑区打开。
- 放大 Obsidian 窗口时布局具备全屏工作台感。
- 工作台中预留热力图区域，空数据时显示温和空状态。
- 缩窄窗口时布局不重叠、不溢出。

### Step 14: 接入刷题集合与本周刷题概览

在工作台展示刷题集合列表、累计刷题数、累计错题数、最近刷题日期、当前轮次和完成状态。同时实现本周刷题概览，展示本周刷题总量、本周错题总量和最近 3 条刷题记录。

验证：

- 新增刷题记录后刷新工作台，统计立即变化。
- 没有刷题记录的集合显示为空状态而不是错误。
- 本周刷题概览能显示本周总题量、错题量和最近 3 条刷题记录。
- 首刷完成集合显示为标灰。

### Step 15: 实现空状态引导

当没有数据时，工作台显示创建第一个刷题集合、记录一次刷题、新增错题卡、新增复盘记录、一键创建示例数据的入口。

验证：

- 全新 Vault 中显示空状态。
- 点击每个入口会打开对应操作。
- 空状态中包含“新增复盘记录”入口。
- 未点击示例按钮时不会创建示例文件。

## Phase 6: 错题卡

### Step 16: 实现错题卡创建弹窗

支持录入行测模块、题型、刷题集合、来源、范围说明、答案、错因、初始掌握度和文字复盘字段。图片为可选项，必须允许创建纯文本错题。保存时根据初始掌握度生成初始 `next_review`。

验证：

- 保存后生成一题一文件的 Markdown 错题卡。
- 正面和背面结构固定且可读。
- 不上传图片也能保存纯文本错题，并能进入复习队列。
- 初始掌握度分别为不会、模糊、基本会、熟练时，`next_review` 分别为明天、3 天后、7 天后、21 天后。
- 必填字段缺失时阻止保存并提示。

### Step 17: 绑定错题与刷题集合

错题卡可绑定刷题集合、集合类型、轮次和来源。绑定时必须保存 `collection_id` 和集合名称。未绑定集合时也允许保存，但应标记为未归档或独立错题。

验证：

- 绑定集合的错题能在集合统计中被识别。
- 集合改名后，已绑定错题仍能通过 `collection_id` 归属到原集合。
- 未绑定集合的错题仍进入复习队列。
- 修改集合名称时不会破坏已存在错题文件的可读性。

### Step 18: 实现错题查询服务

支持按状态、模块、集合、掌握度和复习日期查询错题卡。

验证：

- 查询今日到期错题结果正确。
- 已归档或暂停的错题不进入默认复习队列。
- 缺失部分 frontmatter 的错题不会导致查询崩溃。

## Phase 7: 复盘记录

### Step 19: 实现复盘记录服务

支持创建、读取、更新和查询复盘记录。复盘记录存放在 `Gongkao/Reflections/`，必须包含稳定 `reflection_id`，并支持按日期、模块、复盘类型和关联范围查询。

验证：

- 创建复盘记录后生成独立 Markdown 文件。
- 每条复盘记录都有稳定 `reflection_id`。
- 能按模块、复盘类型和日期范围查询复盘记录。
- 缺失可选关联对象时仍能保存当天整体复盘。

### Step 20: 实现复盘记录弹窗

支持录入复盘类型、关联范围、行测模块、刷题集合、错题卡、触发场景、我的问题、技巧/方法和下次纠偏动作。复盘类型使用固定选项，避免变成自由日记。

验证：

- 可以创建当天整体复盘、模块复盘、集合复盘和错题复盘。
- 必填字段缺失时阻止保存并提示。
- 生成的 Markdown 正文包含固定结构并可直接阅读。
- 关联错题或集合时，frontmatter 保存稳定 ID 和可读名称。

### Step 21: 在工作台接入最近复盘

在工作台展示最近复盘记录，并在快速操作区提供“新增复盘”入口。空状态中也应包含创建复盘记录入口。

验证：

- 新增复盘后工作台刷新并展示该记录。
- 无复盘记录时显示温和空状态。
- 点击复盘记录可以打开对应 Markdown 文件。
- 快速操作中的“新增复盘”能打开复盘记录弹窗。

## Phase 8: 备考努力热力图

### Step 22: 实现每日努力值统计

根据刷题记录、错题复习历史、复盘记录和每日计划完成率，汇总每天的努力值。努力值用于热力图颜色分级，不需要向用户展示具体公式。

验证：

- 有刷题记录的日期努力值大于无记录日期。
- 有复习历史的日期能计入努力值。
- 有复盘记录的日期能计入努力值。
- 每日计划完成率变化会影响对应日期努力值。

### Step 23: 实现热力图组件

在工作台展示最近 90 天或 180 天的备考努力热力图。颜色深浅代表投入强度，无数据日期显示为最低强度或空格。

验证：

- 热力图能按日期连续展示。
- 不同努力值能映射到不同颜色强度。
- 浅色和深色主题下均可读。
- 无数据时显示温和空状态。

### Step 24: 实现热力图交互

悬停某一天时显示日期、刷题数、复习数、复盘数和计划完成率。点击某一天时打开当天计划或当天记录列表。

验证：

- 悬停信息与当天真实数据一致。
- 点击有计划的日期能打开当天计划。
- 点击无计划但有记录的日期能展示或打开当天记录入口。
- MVP 不出现导出分享图入口。

## Phase 9: 图片录入与遮挡

### Step 25: 支持本地图片选择

在新增错题流程中支持从本地选择 jpg、jpeg、png 和 webp 图片，并复制到附件目录。

验证：

- 选择图片后附件文件被复制到正确目录。
- 错题卡 frontmatter 保存相对附件路径。
- 不支持的文件类型被拒绝并提示。

### Step 26: 支持拖拽图片

在新增错题弹窗中支持拖拽图片文件。

验证：

- 拖拽合法图片后显示预览。
- 拖拽多个文件时只接受图片或要求用户选择目标图片。
- 拖拽非图片文件不会报错。

### Step 27: 支持剪贴板粘贴图片

在新增错题弹窗中支持从剪贴板粘贴截图或图片。

验证：

- 粘贴截图后生成预览并可保存为附件。
- 空剪贴板或文本剪贴板不会触发错误。
- 粘贴图片生成的文件名不与已有附件冲突。

### Step 28: 实现矩形遮挡编辑器

用户可以在图片预览上创建、移动、缩放和删除多个矩形遮罩。遮罩坐标以原图自然尺寸保存。

验证：

- 保存后 frontmatter 中存在正确遮罩数据。
- 重新打开错题时遮罩位置与原图区域一致。
- 图片缩放后遮罩仍能正确对齐。

## Phase 10: 复习流程

### Step 29: 实现复习队列生成

查询状态为活跃且下次复习日期不晚于今天的错题，按逾期天数、掌握度和创建日期排序。

验证：

- 到期错题进入队列。
- 未到期错题不进入队列。
- 低掌握度和逾期更久的错题排序靠前。

### Step 30: 实现复习 View 正面

复习正面只展示题目图片、遮罩和正面提示，不展示答案、解析或背面内容。

验证：

- 有遮罩的图片在正面被遮挡。
- 无图片错题仍能显示正面文字。
- 背面内容不会提前出现。

### Step 31: 实现复习 View 背面

用户点击显示背面后，展示完整图片、答案、核心突破口、我的错因和下次提醒。

验证：

- 背面完整显示未遮挡图片。
- 背面文字按固定结构展示。
- 正面和背面切换不会改变原始 Markdown 内容。

### Step 32: 实现掌握度反馈与排期更新

用户选择不会、模糊、基本会、熟练后，更新掌握度、复习次数、上次复习日期、下次复习日期和复习历史。

验证：

- 四种反馈分别生成正确的下次复习日期。
- 复习历史追加记录而不是覆盖旧记录。
- 更新后该卡从今日队列移除，除非排期仍为今天。

## Phase 11: 今日计划与薄弱纠偏

### Step 33: 实现今日计划生成

根据今日到期错题、默认主刷题集合、最近 7 天薄弱与纠偏信号和今日是否已有刷题记录，生成 `Gongkao/Plans/YYYY-MM-DD.md` 每日计划 Markdown。

验证：

- 有到期错题时计划包含复习任务。
- 有主刷题集合时计划包含推进任务。
- 最近存在“思维惯性”复盘时计划包含纠偏提醒。
- 工作台能读取 `Gongkao/Plans/YYYY-MM-DD.md` 并展示计划。
- 今天已有计划时不会无提示覆盖。

### Step 34: 实现每日计划完成率

解析每日计划中的任务勾选状态，并在工作台展示完成率。

验证：

- 勾选和取消勾选任务后完成率正确变化。
- 没有今日计划时显示引导。
- 非计划文件不会被误统计。

### Step 35: 实现薄弱与纠偏提醒

根据最近 7 天错题数、到期复习数、低掌握度错题数和“思维惯性”复盘数识别薄弱与纠偏提醒。

验证：

- 最近 7 天错题最多的模块能被识别。
- 低掌握度错题超过阈值时显示提示。
- 同一模块最近 7 天存在 2 条以上“思维惯性”复盘时显示纠偏提示。
- 工作台不再单独展示“复盘纠偏提醒”组件，纠偏信息合并在该组件中。
- 无足够数据时显示温和空状态。

## Phase 12: 示例数据与收尾

### Step 36: 实现一键创建示例数据

用户主动点击后创建示例专题、示例刷题记录、示例错题卡、示例复盘记录和示例今日计划。文件名明显包含示例字样。

验证：

- 未点击按钮时不会创建任何示例数据。
- 点击后示例数据完整出现。
- 示例数据中包含至少一条“思维惯性”复盘记录。
- 示例数据中包含可让热力图显示不同强度的多日记录。
- 重复点击不会创建难以区分的重复示例。

### Step 37: 完成样式打磨

统一工作台、弹窗、按钮、卡片、遮罩和空状态样式。使用 Obsidian CSS 变量和 `gongkao-` class 前缀。

验证：

- 浅色和深色主题下均可读。
- 窗口变窄时文本不重叠。
- 所有主要操作按钮状态清晰。

### Step 38: 完成发布前检查

检查插件清单、版本、构建产物、README、LICENSE 和发布文件。确认没有引入网络、AI、OCR、数据库或外部社区插件依赖。

验证：
